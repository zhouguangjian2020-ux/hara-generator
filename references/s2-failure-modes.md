# S2 失效模式选择参考

Agent 推理时使用本文档选择每个需 HARA 功能对应的失效模式。

## 11 种失效模式定义

| 模式  | 定义                     | 覆盖关系          |
| --- | ---------------------- | ------------- |
| 丢失  | 功能完全丧失，无法提供预期输出        | —             |
| 非预期 | 功能在不该激活时激活，或输出了非预期的值   | —             |
| 间歇  | 功能时有时无、断断续续            | 极端可被"丢失"覆盖    |
| 过多  | 功能输出量超过预期（如助力过大、制动力过大） | —             |
| 过少  | 功能输出量低于预期（如助力不足、制动力不足） | —             |
| 过早  | 功能激活时机早于预期             | 极端可被"非预期"覆盖   |
| 反向  | 功能输出方向与预期相反（如本应制动却加速）  | —             |
| 振荡  | 功能输出不稳定、反复波动           | 可被"过多"和"过少"覆盖 |
| 部分  | 功能仅部分实现，某些子功能丧失        | 极端可被"丢失"覆盖    |
| 过晚  | 功能激活时机晚于预期             | 极端可被"丢失"覆盖    |
| 卡滞  | 功能卡在某个状态无法变化（如卡滞在制动位置） | —             |

## 选择原则

1. 只选择对该功能有实际工程意义的失效模式
2. 如果一种失效模式在极端情况下可被另一种覆盖，通常不重复选择
3. 从功能的物理特性判断：
   - 状态变化类功能（档位、上下电、充电状态）→ 状态类失效（丢失、非预期）
   - 数值输出类功能（扭矩、温度、制动力）→ 数值类失效（过多、过少）
   - 有方向概念的功能（D/R、加速/减速）→ 考虑"反向"
   - 机械卡滞风险（转向、EPB）→ 考虑"卡滞"
4. 特殊情况注意：
   - 充电需外接电源，不存在"非预期充电"
   - 充放电是两套独立系统，不选"反向"
   - 状态检测类（如高压绝缘监测）不存在"反向"
   - 信息显示类辅助功能可能不涉及安全相关失效

## 10 个 Few-shot 参考案例

### 案例1：转向助力功能

- 子功能：基础助力控制、转向补偿、主动回正、末端软止点保护、转向模式控制
- 失效模式：**丢失、非预期、过多、反向、卡滞**
- 理由：转向助力存在丢失、非预期、过多、反向和卡滞等失效模式

### 案例2：电子驻车制动（EPB）

- 子功能：静态拉起、静态释放、动态制动、外部驻车请求响应
- 失效模式：**丢失、非预期、过多、过少**
- 理由：EPB 为车辆提供驻车制动力，不存在制动力反向；卡滞可被丢失（完全卡死=接合/释放丧失）和非预期（部分卡滞=非预期接合/释放）覆盖，不重复选择

### 案例3：车辆减速控制（行车制动）

- 子功能：防抱死制动 ABS、电子制动力分配 EBD
- 失效模式：**丢失、非预期、过多、过少**
- 理由：制动系统不存在制动力矩反向

### 案例4：档位控制及显示功能

- 子功能：换挡请求及仲裁、换挡控制、档位自动切换、请求 EPB 驻车、档位信息显示
- 失效模式：**丢失、非预期、反向**
- 理由：档位控制只涉及状态变化，不存在数值大小变化；档位有 D/R 方向切换故选择反向

### 案例5：整车高压上下电管理

- 子功能：高压上电管理、高压下电管理、READY 状态管理、DCDC 控制、低压智能补电
- 失效模式：**丢失、非预期**
- 理由：高压上下电只涉及车辆状态变化，不涉及数值变化
- ⚠️ **注意**：另一项目中同名功能选择了 `丢失、非预期、过多、过少`，因为该项目涉及更复杂的 DCDC 硬件设备，需要分析电压/电流的过多过少。**同名功能在不同项目中可能因硬件差异而有不同的模式选择。**

### 案例6：车辆热管理功能

- 子功能：电池冷却、电池温度均衡、电驱系统冷却
- 失效模式：**丢失、非预期、过多、过少**
- 理由：热管理有两套工作模式（加热/冷却），存在温度控制过多过少

### 案例7：车辆扭矩控制

- 子功能：驱动扭矩计算、能量回收、蠕行控制、扭矩限制、车速限制、功率限制等
- 失效模式：**丢失、非预期、过多、过少、反向**
- 理由：扭矩值有大小与方向概念

### 案例8：充放电功能

- 子功能：充电设置、直流充电枪、直流充电控制
- 失效模式：**丢失、过多、过少**
- 理由：充电需外接电源故不存在非预期充电；充放电是两套系统不选反向

### 案例9：高压安全

- 子功能：高压绝缘监测、高压互锁监测、碰撞监测、热失控监测
- 失效模式：**丢失、非预期**
- 理由：只涉及状态检测，不涉及数值大小变化

### 案例10：增程控制系统

- 子功能：增程模式控制、增程器启动控制、增程仪表提示、故障管理等
- 失效模式：**丢失、过多**
- 理由：增程控制只涉及状态检测与控制

## 历史参考案例库

parse 阶段会自动从 `references/s2-lookup-table.json`（104 条历史案例，来自 11 个数据组）中按相似度匹配 Top-3，写入 `intermediate.json` 的每个相关项 `s2_suggestions` 字段。

### 使用方式

1. **查看建议**：读 `intermediate.json` 中该功能的 `s2_suggestions` 数组，每条含 `ref_func_name`、`selected_modes`、`reason`、`similarity`、`match_type`
2. **参考但不强制采纳**：历史案例是工程师在真实项目中的选择，可作为重要参考，但**不是唯一依据**
3. **结合当前项目判断**：重点看当前项目的**子功能列表和功能描述**，判断硬件复杂度是否与参考案例一致
4. **同名冲突处理**：如果 `s2_suggestions` 中出现同名功能但模式不同（带 `note` 字段标注），说明该功能在不同项目中有不同选择，需结合当前项目的子功能列表判断应采用哪种模式

### 匹配层次

| 层次 | 策略      | 相似度      | 说明                |
| -- | ------- | -------- | ----------------- |
| L1 | 功能名精确匹配 | 1.0      | 同域同名 → 最可靠参考      |
| L2 | 核心词包含匹配 | 0.85+    | 去后缀后核心词互相包含       |
| L3 | 序列相似度   | 0.5\~0.8 | difflib 序列比对，作为兜底 |

同域匹配额外 +0.1 加分。仅返回 Top-3，相似度低于 0.5 的不返回。

### 参考案例的局限性

- 11 种失效模式中有 5 种（间歇、过早、振荡、部分、过晚）在所有历史案例中**从未被勾选**，不代表不适用于所有功能，而是工程师认为可被其他模式覆盖
- 参考案例中的模式选择受项目硬件方案影响（如 DCDC 有无、充电协议差异），不可直接套用
- 最终决策应基于当前项目的功能特性，历史案例仅作为验证方向和减少遗漏的工具

## 各域失效模式推荐

### ET 域（Info / 娱乐域）

| 功能分类 | 推荐失效模式 | 说明 |
|---------|------------|------|
| 仪表一般信息显示 | 丢失、非预期、过大、过小 | 显示类功能主要关注丢失（无显示）、非预期（错误显示）、过大/过小（数值偏差） |
| HUD 抬头显示 | 丢失、非预期、过大、过小 | 同仪表显示类 |
| 中控及娱乐系统 | 丢失、非预期、卡滞 | 系统类功能关注死机/卡滞 |
| 车辆导航功能 | 丢失、非预期、过小 | 导航关注定位丢失、路径错误 |
| 手机互联功能 | 丢失、非预期、间歇 | 互联类关注连接稳定性 |
| 驾驶员监测（DMS） | 丢失、非预期、过小 | 监测类关注检测失效、误报、漏报 |
| 乘员监测（OMS） | 丢失、非预期、过小 | 同监测类 |
| 行驶记录仪 | 丢失、非预期、过小 | 记录类关注录制失效 |
| 车辆 X-call | 丢失、非预期 | 紧急呼叫关注呼叫失效/误触发 |
| 车辆远程控制 | 丢失、非预期 | 远程控制关注失效/误触发 |
| 账户设置及登录 | 丢失、非预期 | 设置类关注失效/错误配置 |

**ET 域注意：**
- 信息显示类功能不存在"反向"模式
- "过大/过小"对应显示数值偏高/偏低
- "间歇"用于连接不稳定类功能
- 与驾驶安全直接相关的显示（车速、Ready灯）ASIL 可能较高

### BD 域（B / 车身域）

| 功能分类 | 推荐失效模式 | 说明 |
|---------|------------|------|
| 外部灯光（位置灯/近光灯/远光灯等） | 丢失、非预期、过早、过晚 | 灯光类关注点亮/熄灭失效、时机偏差 |
| 转向灯 | 丢失、非预期、过早、过晚 | 同灯光类 |
| 制动灯 | 丢失、非预期 | 制动灯安全等级较高 |
| 倒车灯 | 丢失、非预期 | 同灯光类 |
| 雨刮系统 | 丢失、非预期、过多、过少、卡滞 | 雨刮有速度控制（过多/过少）和机械卡滞 |
| 后视镜控制 | 丢失、非预期、卡滞 | 电动调节关注卡滞 |
| 车窗/天窗 | 丢失、非预期、卡滞、反向 | 门窗有方向（上升/下降）故考虑反向 |
| 门锁 / 中控锁 | 丢失、非预期、卡滞 | 门锁关注锁止/解锁失效 |
| 儿童锁 | 丢失、非预期 | 同门锁类 |
| 座椅调节 | 丢失、非预期、过多、过少、卡滞、反向 | 座椅有位置调节（方向+量） |
| 充电口盖控制 | 丢失、非预期、卡滞 | 开关类关注卡滞 |
| 低速行人警示（AVAS） | 丢失、非预期、过大、过小 | 声音类关注音量大小 |
| LOGO 灯 / 氛围灯 | 丢失、非预期 | 灯光类 |

**BD 域注意：**
- 灯光类功能一般选"丢失、非预期、过早、过晚"四种
- 有机械运动的功能（雨刮、座椅、门窗）考虑"卡滞"
- 有方向概念的功能（车窗升降、座椅前后调节）考虑"反向"
- 有速度/力度调节的功能（雨刮速度、座椅调节速度）考虑"过多/过少"
