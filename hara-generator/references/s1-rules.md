# S1 HARA 判定规则参考

## 概述

S1（Step 1）判断每个相关项（整车功能）下的子功能是否需要进行 HARA（危害分析和风险评估）。

判定采用两层架构（脚本执行）：
1. **相关项级关键词规则**（按域生效）：相关项名命中关键词 → 其下所有子功能 HARA="否"
2. **子功能级关键词规则**（按域生效）：子功能名命中关键词 → 仅该子功能 HARA="否"

规则未覆盖的 pending 子功能，由 **Agent 自行推理**判定。

## 排除规则表

### 相关项级排除

| 关键词 | 适用域 | 排除理由 |
|--------|--------|----------|
| 安全监控、故障报警 | 全部 | 该功能属于安全机制，根据 ISO 26262 标准不对此类功能进行 HARA 分析 |
| 电耗显示、续航显示 | 全部 | 纯信息显示类功能，不影响车辆运动控制 |
| 增程控制 | P（动力域） | 增程器仅为辅助动力单元，不直接驱动车轮 |

### 子功能级排除

| 关键词 | 适用域 | 排除理由 |
|--------|--------|----------|
| 车辆特殊模式 | 全部 | 特殊测试/工作模式 |
| 车辆模式 | 全部 | 工厂/拖车/测功等特殊测试模式 |
| 仪表提示 | 全部 | 仪表信息提示功能，不直接影响车辆运动控制 |
| 排放测试、排放控制 | P（动力域） | 排放相关功能为法规测试/法规要求，不涉及车辆安全 |
| 故障存储、故障报警（排除词：监测） | 全部 | 通用故障存储及报警属于诊断/安全机制；含"监测"的安全相关报警（如 TPMS 胎压报警）不排除 |

## Agent 推理判断标准

> **核心原则：判断对象是整个相关项，不是单个子功能。** 一个相关项只要核心功能涉及安全，其下所有子功能都纳入 HARA 范围。

### 需要 HARA 的功能类型
- 直接或间接影响车辆运动控制：驱动、制动、转向、换挡、扭矩
- 涉及高压安全：触电风险、火灾风险
- 涉及电池安全：热管理、充放电控制

### 不需要 HARA 的功能类型
- 纯信息显示 / 娱乐功能
- 诊断报警机制本身（非安全功能本身）
- 测试 / 维护模式
- 排放法规相关功能
- 辅助动力单元失效不影响主要运动控制

### 安全侧原则
无法确定时默认判定为"需要 HARA"（宁可多做不遗漏）。

## 章节匹配自检

脚本通过精确→子串→模糊三级匹配将子功能关联到 docx 章节。模糊匹配可能误关联，Agent 在审核 intermediate.json 时必须检查：

1. **重复章节检查**：如果同一相关项下两个 Feature List ID 关联到了相同章节（chapter label 相同），必须人工复核——通常是其中一个匹配错误。例如两个子功能都关联到"3.1.6 转向模式控制"，其中一个可能应为"3.1.3 基础助力补偿"。
2. **描述一致性检查**：子功能描述（description）应与子功能名称（name）语义一致。如果描述明显描述的是另一个功能（如名称是"摩擦补偿"但描述是"转向模式切换"），说明章节匹配错误，需人工修正。
3. **模糊匹配结果检查**：脚本对模糊匹配（相似度 < 1.0）的结果会在日志中标注，Agent 应优先核对这些条目。
4. **功能覆盖检查**：S1 中判定为"是"的功能，必须在后续 S3 HAZOP 中出现。如果 S3 遗漏了某个 S1="是"的功能，`hara prepare --s1` 会报 ERROR。

## 各域专节

### ET 域（Info / 娱乐域）专项判定

**必纳入 HARA 的功能类型（S1=是）：**
- 仪表一般信息显示（车速、电量、功率、驾驶模式、Ready灯等）
- HUD 抬头显示
- 中控及娱乐系统（多媒体、车机系统）
- 车辆导航功能
- 手机互联功能（CarPlay/CarLife等）
- 驾驶员监测功能（DMS，疲劳/分心监测）
- 乘员监测功能（OMS，儿童遗留检测）
- 行驶记录仪功能
- 车辆 X-call（紧急呼叫/救援呼叫）
- 车辆远程控制功能
- 账户设置及登录

**排除原则（S1=否）：**
- 纯警示信息/报警弹窗（属于其他域的安全机制，如 Info_func_0001）
- 软开关设置类（属于其他域附属功能，如 Info_func_0010）
- 纯娱乐内容（视频播放、音乐播放等不影响驾驶安全的功能）

### BD 域（B / 车身域）专项判定

**排除原则（S1=否）：**
- 故障报警类功能（外灯故障报警等，属于安全机制本身）
- 跨域划分功能（方向盘振动→智驾域、碰撞高压下电→动力域、ECALL→座舱域）
- 纯机械控制功能（前舱盖锁控制等机械部件）
- 诊断/故障存储类功能

**必纳入 HARA 的功能类型（S1=是）：**
- 外部灯光（位置灯、近光灯、远光灯、转向灯、制动灯、倒车灯、雾灯等）
- 雨刮系统（前雨刮、后雨刮、洗涤系统）
- 后视镜控制（电动调节、加热、折叠、防眩目）
- 门窗天窗（车窗升降、天窗控制、门锁、儿童锁）
- 座椅控制（电动调节、加热、通风、位置记忆）
- 充电口控制（充电口盖、充电口照明灯）
- 低速行人警示音（AVAS）
- LOGO 灯 / 氛围灯
