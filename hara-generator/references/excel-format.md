# Excel 输出格式规范

## Sheet 结构

输出 Excel 包含以下 Sheet：

### Sheet 1：相关项功能清单 / 相关项功能列表

| 列 | 表头 | 内容 | 合并规则 |
|----|------|------|----------|
| A | 整车功能ID | func_id（如 CS_func_0001） | 按相关项合并 |
| B | 整车层级功能 | func_name（如 转向助力功能） | 按相关项合并 |
| C | Feature List ID | feature_list_id | 按子功能 ID 合并 |
| D | 功能描述 | description（来自章节匹配） | 按子功能 ID 合并 |
| E | 是否进行HARA分析 | "是" / "否" | 按子功能 ID 合并 |
| F | 相关项定义文档 | 输入文档的原始文件名（含完整扩展名，不做截断、清洗或重组；仅首行） | 按相关项合并 |
| G | 相关项内对应章节 | chapter（章节编号） | 不合并 |
| H | 备注 | remark（排除原因） | 按子功能 ID 合并 |

- remark 为 "/" 时不写入（留空）
- 自动识别 Sheet 名：支持"相关项功能清单"（底盘域）和"相关项功能列表"（动力域）

### Sheet 2：失效模式

| 列 | 表头 | 内容 |
|----|------|------|
| A | 整车功能ID | func_id |
| B | 功能异常 / 整车功能 | func_name |
| C-M | 11 种失效模式（丢失、非预期、间歇…卡滞） | 选中打 "√" |
| N | 选择理由 | reason（50-150字） |

- 表头第 1 行为列名，数据从第 2 行开始
- 第 3 行为注释行（原模板有 A3:N3 合并单元格的注释）
- 多条数据时在注释行前自动插入行
- 模板缺失效模式列时自动补齐（补到"选择理由"前）

### Sheet 3：HAZOP 分析（S3 阶段生成）

| 列 | 表头 | 内容 | 合并规则 |
|----|------|------|----------|
| A | 整车功能 ID | func_id | 按功能-模式组合合并 |
| B | 整车功能 | func_name | 按功能-模式组合合并 |
| C | 功能失效模式 | 失效模式名（丢失/非预期/...） | 按功能-模式组合合并 |
| D | 功能异常表现 | 具体异常描述 | 不合并 |
| E | 功能失效 ID | `{域}_MF_{功能序号}_{序号}` | 不合并 |
| F | 整车危害 | 危害描述 | 不合并 |
| G | 关联 HARA | 危害 ID 范围（S3 阶段留空，S4 写入时自动回填） | 不合并 |

- 一个功能-模式组合可有多行异常表现
- 第一行写入全部字段，后续行前 3 列留空（合并）
- 有模板时：Row 1 为"HAZOP分析"大标题（保留不动），Row 2 为列标题（保留不动），数据从 Row 3 开始
- 无模板时自动创建（Row 1 大标题 + Row 2 列标题 + Row 3 起数据），含表头样式和列宽
- 有模板时使用模板中的"HAZOP 分析" Sheet

### Sheet 4：HARA 分析（S4 阶段生成）

19 列 A-S，2 行表头（Row 1 分组表头，Row 2 列标题），数据从 Row 3 开始。

| 列 | 表头 | 内容 | 说明 |
|----|------|------|------|
| A | 危害事件ID | `{域}_hzrd_{功能2位}{3位流水}` | 如 CB_hzrd_02001，功能内连续编号 |
| B | 整车功能 | func_name | 每行都写（不合并） |
| C | 功能失效ID | failure_id | 如 CB_MF_0002_01 |
| D | 功能异常表现 | anomaly | 来自 S3 HAZOP |
| E | 整车危害 | hazard | 来自 S3 HAZOP |
| F | 运行场景 | scenario | 驾驶和运行情况 |
| G | 危害事件描述 | description | 场景+后果的完整描述 |
| H | 严重度(S) | 0-3 | S=0 时 J/L 列留空 |
| I | 对"S"的理由 | severity_reason | 含 ΔV 和伤害等级 |
| J | 暴露概率(E) | 1-4 或空 | S=0 时留空 |
| K | 对"E"的理由 | exposure_reason | 含运行场景频率 |
| L | 可控性(C) | 0-3 或空 | S=0 时留空 |
| M | 对"C"的理由 | controllability_reason | 含驾驶员可控比例 |
| N | ASIL | 空白/QM/A/B/C/D | S=0 时留空（E/C 及其理由留空）；S>0 且 C=0 时为 QM，其余查表 |
| O | 安全目标 ID | `{域}_SG_{功能2位}{3位流水}` | 每个 ASIL A-D 事件独立编号；QM 或 S=0 时留空 |
| P | 安全目标 | safety_goal | ASIL A-D 时必填；QM 或 S=0 时留空 |
| Q | 安全状态 | safe_state | ASIL A-D 时必填；QM 或 S=0 时留空 |
| R | FTTI | ftti | 如 500ms、200ms、1s；QM 或 S=0 时留空 |
| S | 注释 | note | 工程判断例外说明等 |

**分组标题行**：每个功能前有一个标题行，合并 A:E，格式 `{func_id}：{func_name}`（全角冒号），蓝底加粗。

**skip 行**：skip=true（"不涉及"）不生成任何行。

**列宽**：A=18, B=14, C=16, D=16, E=28, F=28, G=40, H=6, I=30, J=6, K=30, L=6, M=30, N=8, O=16, P=24, Q=24, R=10, S=20。

**对齐**：H/J/L/N 列居中；A/C/O/R 居中自动换行；其余左对齐自动换行。全表 thin border。

**HAZOP G 列回填**：写入 S4 时，HAZOP 分析表的 G 列"关联 HARA"自动填入对应 failure_id 的 ID 范围（如 `CB_hzrd_02001~CB_hzrd_02012`）。

### Sheet 5：整车安全目标（S5 阶段生成）

模板双区结构（Row1-3 为合并大标题，Row4 为表头，数据从 Row5 开始）：左区为事件级明细，右区为整车级汇总，F 列为序号列。

**左区 A-E（事件级明细，每个非 QM 有安全目标的危害事件一行）**

| 列 | 表头 | 内容 |
|----|------|------|
| A | 安全目标ID | 事件级 ID，如 `CB_SG_01001`（来自 S4 validate 分配） |
| B | 安全目标 | 事件级安全目标文本 |
| C | ASIL | 事件级 ASIL 等级（A/B/C/D） |
| D | 安全状态 | 事件级安全状态 |
| E | FTTI | 事件级 FTTI |

**F 列**：序号，每个 SG 组递增（1, 2, 3…），写在组首行，组内纵向合并

**右区 G-L（整车级汇总，每个唯一安全目标只在该组首行填写）**

| 列 | 表头 | 内容 |
|----|------|------|
| G | 整车安全目标ID | 整车级编号，如 `CB_SG_VH_0001`（S5 分配） |
| H | 安全目标合并 | 去重后的整车级安全目标文本 |
| I | ASIL | 取所有关联事件的最高 ASIL（D>C>B>A） |
| J | Safe State | 整车级安全状态 |
| K | FTTI | 整车级 FTTI |
| L | 备注 | 留空 |

**排列规则**：事件按整车级 SG 分组，同一 SG 的事件连续排列；组间顺序按 SG 编号（ASIL 降序，同 ASIL 按 HARA 表首次出现顺序）；整车级汇总（G-L）写在每个 SG 组的首行，后续同组事件的 G-L 留空。

**合并规则**：每个 SG 组写完后，F-K 列按组纵向合并（F 序号、G 整车ID、H 安全目标、I ASIL、J Safe State、K FTTI），L 备注列不合并，A-E 事件级明细不合并。

**特殊情况**：ET 域（座舱）等全 QM 域无非 QM 事件时，S5 输出 0 条安全目标，该 Sheet 仅保留表头（`sg generate` 仍须执行，由脚本判定为空）。

## 写入流程

1. 解除数据区已有合并单元格
2. 清空旧数据
3. 逐行写入 S1/S2/S3/S4 结果
4. 重新合并单元格（按规则）
5. S4 写入时自动回填 HAZOP G 列 ID 范围
6. S5 写入整车安全目标 Sheet（左区事件级明细 + 右区整车级汇总，F-K 列按 SG 组合并）

## 模板兼容性

- 支持底盘域和动力域两种模板格式
- 支持无模板模式（自动生成简版 Excel，含两个 Sheet、表头样式和边框）
- 支持模板 bytes 流（Aily 部署场景）
